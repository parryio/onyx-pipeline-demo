# PDR 1: Project Layout & Structure (Authoritative)
**Version:** 2.2.0  
**Date:** 2025-09-07  
**Scope:** Phases 1-5 (Onyx Scribe, Golden Pipeline Core, Ritual Player UI) + Out-of-Band Enrichment (Phase E)  
**Author:** AI Assistant

---

## 1. Executive Summary & North Star Alignment
This PDR defines the authoritative repository structure, naming conventions, and file management policies for the Golden Pipeline project. Version 2.2.0 formally introduces an Out-of-Band Enrichment path (Phase E) to support AI-assisted semantic extraction while preserving the pipeline's determinism, provenance, and offline reproducibility. The guiding rule is:

> Immutable Text, Mutable Insight. Phases 1-2 produce the auditable, immutable text layer. Phase 3 consumes a frozen enrichment cache (built out-of-band by Phase E) to generate structured, reproducible insights. No phase in the main pipeline mutates source text.

North Star: "Golden Pipeline - powered by Onyx Scribe and Onyx Hall - is a deterministic, faithful, and scholarly platform where rituals become guided experiences, symbols become comparative knowledge, and seekers of all levels find a reproducible path to wisdom. Rooted in manifest-level provenance, it bridges ancient traditions with predictive-processing insights and chaos-magick framing, without compromise to the source."

## 2. Contracted Repository Layout
The structure below is canonical and authoritative. New top-level directories require a version bump to this PDR.

```
/ (repo root)
├─ .github/             # CI/CD workflows, policy checks, and GitHub Actions
├─ artifacts/           # Immutable, deterministic pipeline outputs (versioned by phase)
│  ├─ phase1/           # Onyx Scribe - Ingest artifacts
│  ├─ phase2/           # Onyx Scribe - Index/Enrichment artifacts
│  ├─ phase3/           # Golden Pipeline - Parsing artifacts
│  ├─ phase4/           # Golden Pipeline - Orchestration artifacts
│  ├─ phase5/           # Ritual Player UI - Display artifacts
├─ config/              # Canonical runtime configuration (onyx.yml)
├─ datasets/            # NEW: Version-controlled inputs external to the pipeline (e.g., enrichment cache)
│  └─ phase3/           # enrichment_cache.jsonl (frozen input to Phase 3; produced by Phase E tooling)
├─ docs/                # Project documentation, PDRs, changelogs
├─ golden_pipeline/     # Primary Python package for Phases 3 & 4 CLI + runtime
├─ lexicons/            # Deterministic curated YAML lexicons powering Phase 3 entity parsing
├─ Library/             # Canonical corpus root (primary sources: PDFs, images, audio, text)
├─ onyx_scribe/         # Primary Python package for Phase 1 & 2 CLI + runtime
├─ ritual_player/       # Primary Python package for Phase 5 (UI data generation)
├─ scripts/             # Orchestration & gate entrypoints (high-level calls to packages) (LEGACY: build_kits.py deprecated)
├─ tests/               # Unit, integration, and end-to-end tests for all phases
├─ tools/               # Shared utilities, schemas, helper scripts
│  └─ schemas/          # JSON Schemas (Required for P1-5; Phase E cache schema included)
└─ tmp/                 # Ephemeral scratch space (ignored by Git)
```

Clarification on Library/ (Unaffected): Library/ remains the canonical corpus root and must deterministically contain all primary source media (PDFs, images, audio, plain text) that the pipeline supports. All primary content in Library/ is treated as immutable input.

Clarification on datasets/ (New): datasets/ contains external, versioned inputs that are not generated by the pipeline itself but are consumed by it. The initial use case is datasets/phase3/enrichment_cache.jsonl, authored by the separate enrichment tool (Phase E). This directory is tracked by Git (or shipped as a release asset) and is read-only from the pipeline's perspective.

## 3. Naming Conventions & IDs
Deterministic naming and ID generation enable traceability and reproducibility across all phases.

- JSONL files: lower_snake_case.jsonl (LF line endings, UTF-8).
- Indices: explicit subfolder + stable basename, e.g., phase2/search/bm25.index.
- Embeddings: embeddings.<model_slug>.jsonl (ASCII slugs [a-z0-9._-]+, pinned in config/onyx.yml).
- IDs:
  - doc_id: doc_<sha256[:12]> of canonical source bytes.
  - asset_id: asset_<sha256[:12]> of canonical binary asset bytes (images, audio).
  - chunk_id: <doc_id>_<zeroPaddedSeq5> (unique per chunk within a doc).
  - entity_id: ent_<type_slug>_<sha256[:12]> (from normalized value + type).
  - correspondence_id: corr_<source_type_slug>_<target_type_slug>_<sha256[:12]>.
  - ritual_step_id: <kit_id>_<zeroPaddedSeq5>.
- Enrichment cache keys (Phase E): cache rows are keyed by chunk_hash + prompt_hash. The pipeline never synthesizes cache keys; it only reads them.

---

## 4. Commit / Ignore Policy
- Tracked: Source code, configuration, scripts, tests, documentation, PDRs; deterministic artifacts in artifacts/phase1-5/ (only on release branches); datasets/phase3/enrichment_cache.jsonl (or published as a release asset).
- Ignored: tmp/, venvs, caches, build metadata (*.egg-info/), notebooks unless required.
- Prohibited (Gate Failures): Non-deterministic pipeline outputs, CRLF line endings, non-UTF-8 in deterministic files.

Default Branch Baseline: artifacts/phase{1-5}/ must contain only .gitkeep. datasets/ MAY be populated and tracked; if not tracked, a release tag MUST supply a matching dataset asset (with a recorded digest) for reproducibility.

---

## 5. Baseline (Default Branch)
- artifacts/phase1-5/: only .gitkeep.
- config/onyx.yml: present, with all model slugs and parameters pinned.
- datasets/phase3/enrichment_cache.jsonl: optional; if absent, phase3.require_cache=true will cause the pipeline gate to fail on release builds.

## 6. Canonical File Set by Phase & Auxiliary Directory
Phase 1 - Onyx Scribe: Freeze / Ingest (artifacts/phase1/)
- manifest.jsonl, chunks.jsonl, events.jsonl, quarantine.jsonl, media_assets.jsonl
Auxiliary (if enabled): metrics.json

Phase 2 - Onyx Scribe: Index / Enrichment (artifacts/phase2/)
- search/bm25.index, embeddings.<model_slug>.jsonl, entity_index.jsonl, provenance.jsonl
Auxiliary (if enabled): search/bm25.index.sha256

Phase 3 - Golden Pipeline: Parser Plugins (artifacts/phase3/)
- entities.jsonl, correspondences.jsonl, ritual_steps.jsonl, doc_metadata.jsonl
  - entities.jsonl is produced via deterministic lexicon-driven parsing (lexicons/*.yaml) with
    canonical normalization and reproducible span extraction. Cache (datasets/phase3/enrichment_cache.jsonl)
    may augment future semantic fields but is not required for lexicon matches.
Auxiliary: metrics_phase3.json (includes cache digest and rule metrics); entities.jsonl.metrics.json (optional detailed extraction stats)

Phase 4 - Golden Pipeline: Orchestration (artifacts/phase4/)
- kits/<kit_id>.kit.json, kits/<kit_id>.kit.lean.json, kit_index.jsonl, crosslinks.jsonl, derivations/collapse_map.jsonl

Phase 5 - Ritual Player UI: Display (artifacts/phase5/)
- ui_catalog.jsonl, assets_manifest.jsonl, pipeline_digest.jsonl

Auxiliary (Non-Contract) Directory:
- artifacts/aux/ (triage, samples, debug). Excluded from gates & pipeline digest.
- Examples: quarantine_triage.jsonl, *.sample.jsonl, legacy gold/ outputs, kits.index.json (legacy).

Deprecations:
- scripts/build_kits.py (legacy, not invoked by CI).

Phase E - Enrichment (Out-of-Band Dataset, not an artifact):
- datasets/phase3/enrichment_cache.jsonl (sorted by key; LF; UTF-8)
  - Each entry is the raw model response plus metadata sufficient to deterministically re-play downstream:
    {chunk_hash, prompt_hash, model, seed, system_fingerprint, timestamp_policy:"elided", raw_response:{...}}
  - No timestamps or nondeterministic values may be present in cache rows (replace with stable sentinels).

## 7. Schemas
Required JSON Schemas (minimum set for P1-5 + Phase E cache):
- manifest, chunks, events, quarantine, media_assets
- provenance, embeddings, entity_index
- entities, correspondences, ritual_steps, doc_metadata
- NEW: enrichment_cache (Phase E dataset shape)
- kits, kit_index, crosslinks, ui_catalog, assets_manifest

All schemas live under tools/schemas/ and are versioned. Any change requires bumping both the schema $id and this PDR's version.

---

## 8. Run Surfaces & Execution Model
- Gold Path (Full Pipeline 1->5):
  ```bash
  onyx pipeline run --root "Library" --artifacts "artifacts" --config "config/onyx.yml"
  ```
- Phase runners: onyx phase1, onyx phase2, onyx phase3, onyx phase4, onyx phase5.
- Enrichment tooling (Phase E): onyx enrich (explicit, operator-driven; never called by CI).
  - Produces/updates datasets/phase3/enrichment_cache.jsonl.
  - Pipeline phases consume cache read-only.

---

## 9. Anti-Bloat Rules
- No new top-level directories without updating this PDR (except the addition of datasets/ herein).
- Temporary files confined to tmp/.
- Large binaries live under Library/ (Git LFS for files >100MB). Large datasets may be shipped as release assets.

---

## 10. CI / Policy Enforcement (Must Fail PRs on Violation)
- Baseline state: artifacts/phase{1-5}/ must be empty (.gitkeep only).
- Green gates: All pipeline phases must pass from scratch, offline.
- Encoding & line endings: UTF-8 and LF only.
- Artifact containment: No unexpected files under artifacts/phase{1-5}/.
- Network ban: Phases 1-4 must not make any network calls.
- Cache digest pin: Release builds must record the sha256 of datasets/phase3/enrichment_cache.jsonl in artifacts/phase3/metrics_phase3.json and verify it in the gate.

---

## 11. Versioning & Change-Control
- PDR uses SemVer. Structural changes bump the minor or major version.
- Schema changes bump both the schema $id and this PDR's version.
- Phase E cache evolution is managed via dataset versioning (Git or release assets) and digest pinning in metrics_phase3.json.

---

## Appendix A - Enrichment Dataset Notes (Normative)
- Sorting: by (chunk_hash, prompt_hash).
- Newlines: \n normalized; file uses LF line endings.
- No timestamps/UUIDs are permitted. Use stable sentinels or omit.
- All raw_response payloads must be valid JSON objects. Free text must be embedded as strings with proper escaping.
